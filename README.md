# 校園最短路徑導航

大一程式設計期末專題。在校園地圖上選起點和終點，程式用 **Dijkstra 演算法** 找出最短的走路路線，畫在地圖上，並列出每一段要走幾公尺、在哪裡轉彎、大約要走幾分鐘。

## 功能

- 輸入起點、終點時會自動推薦地點（可以打代號，例如 `j`，或部分名稱，例如「圖書」、「學生 停車」）
- 也可以直接點地圖：第一下是起點、第二下是終點
- 可以加一個途經點（可不填），例如「宿舍 → 7-11 → 教室」
- 找到的路線用紅線沿著道路畫出來，起點綠色、終點紅色
- 右邊列出每一站、每段距離、方向和轉彎（直走／左轉／右轉／迴轉）
- 顯示總距離和預估步行時間（走路速度設定為每分鐘 70 公尺；上坡每爬 1 公尺多算 8 公尺的時間）
- **坡度**：勾選「最省力路線（避開上坡）」會找比較不累的路；結果區會列出總共上坡、下坡幾公尺，每一段標出坡度（超過 8% 標「陡」）。地點要在 JSON 填 `elevation`（海拔）才有作用
- **比較三種演算法**：同一段路用 Dijkstra、A*、Bellman-Ford 各找一次，三條路線用紅、藍、橘疊在地圖上，右邊列出路線長度、檢查了幾次道路、花了幾毫秒，並寫出結論
- 字型會自動挑電腦裡有的中文字型；Windows 螢幕縮放 125%、150% 時字不會糊掉，地圖上的名稱有白底
- 「交換起點和終點」按鈕，可以馬上查回程
- 螢幕比較小時（例如 1366 寬的筆電、投影機），地圖會自動縮小，右邊面板不會跑出螢幕
- 地圖資料檔不見或格式錯誤時，會跳出視窗用中文說明原因（例如「JSON 格式有錯：第 12 行」）

## 執行環境

- Python 3（只用內建功能：`tkinter`、`json`、`heapq`、`math`、`unittest`，不用安裝任何套件）
- 字型優先用 Windows 內建的「微軟正黑體」，沒有的話依序找蘋方、Noto Sans CJK、文泉驛（見 `config.FONT_CHOICES`）

## 執行方式

在 `campus_nav` 資料夾裡執行：

```
python main.py
```

## 地圖資料格式

`data/map_data.json` 裡有 74 個點、86 條道路。點分成四種：

| type | 意思 | 數量 |
|------|------|------|
| `building` | 建築（教學大樓、宿舍） | 12 |
| `facility` | 設施（球場、停車場、湖） | 18 |
| `gate` | 出入口 | 2 |
| `junction` | 路口（不能選，只用來連接道路） | 42 |

格式範例（數字只是示範）：

```json
{
  "nodes": [{"id": "J", "name": "J 圖書館…", "type": "building", "x": 190, "y": 215, "lat": 22.90, "lng": 120.46}],
  "edges": [{"from": "A", "to": "J", "distance_m": 45, "path": [[190, 215], [200, 230]]}]
}
```

- `x`、`y`、`path` 是地圖上的像素座標，只用來畫圖和判斷方向
- `distance_m` 是道路的實際距離（公尺），Dijkstra 用它當權重
- `elevation`（可以不填）是地點的海拔（公尺），用來算坡度；沒填的地點當作平路。
  目前的數字是用經緯度向 Open-Meteo 查 Copernicus 90 公尺解析度的地形資料，再和周圍約 45 公尺的 8 個點加權平均（讓坡度平滑，不會一格一格跳），只是估計值；
  校園最高是 J 圖書館一帶（約 156 公尺），最低是北側出入口（約 82 公尺）。實際走過覺得不對，直接改 JSON 裡的數字就好
- `lat`、`lng` 是地點的經緯度，A* 用它算「離終點的直線距離」；`tests/test_data.py` 也用它檢查距離資料：
  沿著道路走的 `distance_m` 不可能比經緯度算出的直線距離還短；
  另外每條路的「公尺 ÷ 像素長度」都要在合理範圍（目前都在 0.69 ~ 0.91），超出就代表距離或折線打錯了
- 道路是雙向的；`path` 是沿著道路的折線，沒給的話就畫直線

## 演算法說明

1. 把地圖存成「鄰接表」：每個地點記錄它連到哪些地點、距離多少。
2. Dijkstra：用 `heapq`（優先佇列，每次都能拿出目前距離最短的那個）從起點開始往外擴展，每個地點第一次被拿出來時，就確定是最短距離。
3. 走到終點就提早結束，再沿著「每個地點是從哪裡走過來的」紀錄往回推，得到完整路線。
4. 走不到時回傳空路線和無限大距離；起點或終點不存在時直接報錯。
5. 有途經點時跑兩次 Dijkstra（起點 → 途經點、途經點 → 終點），再把兩段路線接起來、距離相加。

### 坡度（最省力路線）

每段路的權重改成「距離 + 上坡高度 × 8」，下坡不加。8 倍來自登山常用的奈史密斯規則（爬高 600 公尺大約和平地走 5 公里一樣久）。演算法本身不用改，只是權重換了，所以三種演算法都可以找最省力的路。

### 三種演算法比較

| 演算法 | 做法 | 找到的路線 | 工作量 |
|--------|------|-----------|--------|
| Dijkstra | 每次處理離起點最近的地點，到終點就停 | 最短 | 中 |
| A* | Dijkstra 再加上「離終點的直線距離」估計，往終點方向優先找 | 最短（估計值不會超過真正距離） | 最少 |
| Bellman-Ford | 每一輪把全部道路檢查一遍，直到沒有變化 | 最短（還能處理負距離） | 最多 |

在這張校園地圖上實測（每種跑 200 次取平均）：

| 路線 | 演算法 | 處理地點／輪數 | 檢查道路次數 | 平均時間 |
|------|--------|---------------|-------------|---------|
| J → I（478 公尺） | Dijkstra | 44 個地點 | 54 | 約 0.02 毫秒 |
| | A* | 17 個地點 | 23 | 約 0.02 毫秒 |
| | Bellman-Ford | 7 輪 | 976 | 約 0.17 毫秒 |

勾選「最省力路線」的例子：網球場 → F 教學大樓，最短路線 396 公尺要爬 28 公尺；最省力路線 401 公尺只爬 11 公尺（多走 5 公尺，少爬 17 公尺）。

三種找到的距離完全一樣；A* 檢查的道路不到 Dijkstra 的一半，Bellman-Ford 多了將近 20 倍。地圖只有 74 個點，所以時間差距很小，地圖越大差距越明顯。
