校園最短路徑導航

實踐大學高雄校區・Dijkstra 演算法

建築 設施 出入口 最短路線

點地圖上的圓點：第一下選起點，第二下選終點。手機上地圖可以左右滑動。

專題介紹

動機

剛進實踐大學高雄校區時，校園在山坡上、建築分散，常常不知道從宿舍到教室、從圖書館到體育館要怎麼走最快。 所以我把校園做成一張「圖」，讓程式幫忙找出最短的走路路線。

怎麼把校園做成點和線

  • 點（node）：建築、設施、出入口都是一個點，另外在道路交叉的地方放「路口」點，共 74 個點。
  • 線（edge）：兩個點之間如果有路可以直接走到，就連一條線，共 86 條，每條線記錄實際距離（公尺），這就是「權重」。
  • 道路是雙向的，所以每條線兩個方向都可以走。資料存在 map_data.json，程式讀進來後整理成「鄰接表」：每個點連到哪些點、距離多少。

Dijkstra 演算法

  1. 起點的距離設為 0，其他點都是「還不知道」。
  2. 每次從還沒確定的點裡，挑出目前距離最短的那一個（用優先佇列 heapq，很快就能拿到最小的）。
  3. 這個點的距離就確定了。看它的每個鄰居：如果「經過它」走到鄰居比原本知道的還短，就更新鄰居的距離，並記下「鄰居是從這裡走過來的」。
  4. 一直重複，直到終點被確定為止；再從終點沿著記錄往回推，就得到完整路線。

因為每條路的距離都不是負的，第一次被挑出來的點一定已經是最短距離，所以結果保證是最短路線。 網頁版的 JavaScript 是照 Python 版一行一行改寫的，所有 74 × 74 組起點、終點的結果都和 Python 版一模一樣。 步行時間用每分鐘 70 公尺估算。
